# 封印献祭：把终局从「付钱」改成「亲手凿开」

状态：in-progress（实现已落地并实测；价格与通关时长等最终调参一起过）
更新：2026-09-08

> 这份 spec 写于两版经济并存时期，通篇按「只改宝石版、金币版一行不动」的前提展开。
> **金币版已于 2026-09-07 删除**，那条约束随之作废——`ECON.sealOffering` 现在恒为真，
> `checkFinaleTrigger()` 里那句让路的 `return` 和 `finale.forcedSite` 的空值回退都成了死枝，
> 留着是因为它们各占一行、且都在战斗改造正在动的区域附近，等那边落地再一起清。

## 为什么要改

两次自动机通关（135.2s / 138.8s，采样间隔 4 秒）量出三个互相咬着的毛病，它们其实是同一个洞：

**P1 后 40% 时间金币没有出口。** 主城 Lv4 在 82.6 秒买完，那是最后一个金币消费点。之后 52.6 秒又挖出 164 枚，占全场产出的 44%，一枚花不掉。挖矿是这个游戏的核心动词，金币是它唯一的即时反馈——在最后四成时间里这个反馈是空转的。

**P2 锄头 Lv4 是最长的一段投入，却不解锁任何东西。** 82.6 → 117.8 秒，35.2 秒零进度事件，是中位间隔（11.2 秒）的 3.1 倍。Lv4 不开新矿层（封印矿 `requiredPickaxe: 5`），只提速；它自带的横扫还当场退回 10 颗永远花不掉的高级宝石——这个升级把自己的成本退回成了垃圾。

**P3 终局的因果链弱。** CTA 前玩家最后一个主动操作是「站在地贴上付 14 颗钻石」，1.3 秒后巨龙自己破土。他记住的是付款。

一个改动能同时修掉三条：**让封印矿变成金币的终点站，而打开它的资格由锄头 Lv4 提供，打开的动作由玩家自己完成。**

## 设计

### 出现条件

献祭点只有一个前置：`petEvolved`。

**要宠物进化**，是因为终局对峙的构图里站着玩家和他的龙，而 CTA 的文案写死了「你的巨龙已经进化完成」。不卡这条，玩家可能带着一只没进化的幼龙触发终局，画面和文案一起对不上。

原先还要**锄头满级**，理由是「给 Lv4 一个解锁物」。这条 2026-09-08 去掉了，见下面「砍掉终局那趟往返」——高级矿的 `requiredPickaxe` 是 3，玩家凿穿它的时候手里只有 Lv3，这道前置的唯一效果是把他赶回城里买一次 Lv4 再走回来。Lv4 仍然值得买（提速，外加那一次横扫直接清空三层矿），只是不再拦着终局。

### 位置

扇形中线上，封印矿内壁前 1.6 米，半径 41.8。

这个半径是被夹出来的，不是挑出来的：高级矿外缘 40.2、封印矿内缘 43.4，中间那条 3.2 米宽的走廊是唯一站得住人的地方。41.8 正好是它的中线，也正好是终局对峙时 `standPoint` 的半径——那条走廊本来就是为「玩家站在墙根底下」留的。

这个位置带来一个不用额外做的好处：`CONFIG.mineRange` 是 3.4，而封印墙离献祭点只有 1.6 米。**玩家站在献祭点上付款时，自动索敌会一直把封印墙选成目标，他全程在抡锄头砸墙。** 付完的下一下就砸开了。不需要为「最后一击」新做任何输入或演出——因果链从现有的自动索敌里自己长出来。

代价是付款期间会反复触发 `rejectMine` 的「凿不开」提示和 clang。clang 要留着（他确实在砸墙），提示要压掉（那句话此刻是错的——墙马上就开了）。

## 砍掉终局那趟往返（2026-09-08）

### 问题

实测把这段路量了出来。凿穿高级矿之后，玩家要做的事和它们在哪：

| 阶梯 | 半径 | 时刻 |
|---|---|---|
| 手动凿穿高级矿 | 38.2 | 88.3s |
| 锄头 Lv4（地贴在城里） | 6.4 | 97.3s |
| 宠物进化（地贴在城里） | 9.4 | 105.4s |
| 献祭点出现 → 破封 | 41.8 | 105.4s → 111.8s |

**23.5 秒、149 米**，占整局 19% 的时长和 29% 的路程，而且是一段纯粹的回头路：走到墙根、发现还差两个升级、走回城里买、再走回同一堵墙。

上面「已知取舍」里那条「多一段路」原本把它算作有意的前奏（揣着一整场的金币走向封印）。真人过局之后判断反过来了——那读不成前奏，读成重复。

### 改法

三张贴都摆到封印走廊上（半径 41.8，`SEAL_OFFER_RADIUS`），沿弧每隔 4.4 米一张：

```
        进化 0/14          献祭 0/120         锄头 0/3
      (-4.4, -41.6)       (0, -41.8)       (+4.4, -41.6)
```

偏 4.4 米是被贴宽夹出来的：`zoneTileSize` 是 3.4，错开 4.4 留出一米的缝，读成前后两个站点而不是同一张贴换了图标。东西分侧接着城里那条站位规律——锄头（吃宝石）在东，吃钻石的在西。

于是终局是一路向外的：**凿穿高级矿 → 就地打怪攒钻石 → 锄头 Lv4 → 进化 → 破封**。

进化台是「挪」而不是「取消」：CTA 文案和对峙构图都要求那条龙已经进化，所以它必须仍然排在破封之前，只是不该排在三十米外。

### 锄头贴为什么要两个槽位

**前三级绝不能挪出城。** Lv2、Lv3 是凿开中级矿和高级矿的钱，而这条走廊在那两道墙之后——开局就把贴摆在外面，玩家买不到 Lv2、也就凿不开中级矿，整局当场死锁。

只有 Lv4 那一级不解锁任何矿层（高级矿要 3，封印矿要 5，永远够不着），它才可以跟着终局搬到墙根。所以 `TILE_SLOTS` 里有 `pickaxe` 和 `pickaxe-last` 两个槽，由 `tileSlot(id)` 按 `pickaxeLevel` 挑；`completePickaxe` 重新布防时调 `moveZone` 把贴搬过去。创建和重新布防两条路都走 `tileSlot`，免得规则各写一份。

### 顺带要跟着改的四处

- **`guideThroughGate` 要判目标在不在自由圆里。** 它是为「目标在矿区、玩家在城里」准备的；锄头贴现在两种情形都有，对城内目标那套绕行是反向的。详见「踩到的坑」。
- **破封时收掉所有还亮着的地贴。** 以前不用管——残留的贴全在城里，离破封点四十米，天然落在画面外。现在锄头那张离破封点只有 4.4 米，玩家一路没踩它就破了封的话，一张 0/3 会横在巨龙挣出来那一拍的画面里。
- **「封印矿凿不开」改成整局只说一次。** 那两张新贴离封印墙也只有 1.6 米，玩家会在墙根待上二十来秒，付款期间自动索敌一直咬着封印墙，按 3.2 秒一次能刷出七八条。clang 和弹开照旧（他确实在砸墙）。
- **箭头对这两张贴要走 `guideThroughGate`。** 它们现在在矿区，而玩家可能还在城里。

### 不用管的两件事

- **进化台会不会摆在一堵完好的矿墙后面。** 不会：它挂在武器满级上，而武器 Lv2→Lv3 要等破壳，整条钻石单轨天然排在破高级矿之后。塞满钱的对抗实测里高级矿 65.8s 破、进化台 93.4s 才出现。
- **锄头 Lv4 那张贴会。** 它在 `pickaxeLevel` 到 3 时就搬出去了，可能早于破墙，此时箭头指向墙后一个走不到的点。但这不会卡死：玩家顶着墙走，自动索敌咬住高级矿，他会把墙挖穿——对抗实测里这一版反而更早破墙（65.8s）。箭头此刻说的是「继续往外」，没说错。

### 三段状态

献祭点是一张普通的 `zone`，走 `createZone` / `updateZones` 那套：走上去、金币从背上流进去、付满触发回调。复用付款节奏、`flyCoinTo`、音效、地贴贴图、引导箭头，新增的只是判定分支。

1. **未出现** —— 条件没齐。
2. **收款中** —— 玩家站上去，金币往裂缝里流。同时他在砸墙，墙不动。
3. **已激活（`sealArmed`）** —— 付满。提示「封印松动了」，箭头改指墙本身。下一次挥镐进 `breakSeal()`。

### 触发链改动

`checkFinaleTrigger()` 现在是 `petEvolved && breachedByTier.high >= 1`。宝石版下要把这条关掉，否则进化完成的那一刻终局就自己起来了，献祭点还没来得及出现。

```
ECON.sealOffering 存在  →  终局只能由 breakSeal() 触发
ECON.sealOffering 为空  →  维持原判定（金币版）
```

`updateProgressWatchdog` 里那条「进化了且高级矿清空就补记破封」的兜底同理，宝石版下不再调 `checkFinaleTrigger`。

### 破封点跟着献祭点走

`sealedDragonSite()` 挑的是**离玩家最远**的那段封印矿——它的前提是「终局可能在玩家还在城里时触发」。现在触发点就是玩家脚下，这条规则会让龙从他背后的另一头钻出来，因果链当场断掉。

所以 `breakSeal()` 要写下 `finale.forcedSite`，`startFlameDragonIntro()` 优先用它。构图不受影响：`braceForBattle` 本来就会把玩家挪到 `standPoint`（破封点内侧 4 米、侧向 7 米）。

### 价格

150 金币。**实测后下调到 120**——见下面「实测」。

实测在锄头 Lv4 那一刻玩家手上有 118 枚，Lv4 的横扫再给 46（`sweepBounty.high`），进化只花钻石，所以走到墙前时大约 160~165 枚。定 150 是让他**几乎清空**——献祭要读成「把整场攒的都砸进去」，留个零头比刚好归零更可信，也给真人玩家（挖得比自动机少）留一点余量。

不够时由 `ensureProgressAffordable()` 兜底，和别的地贴同一条路径，不特殊处理。

## 实测

**献祭与破封落在同一时刻**（第一次实测 131.8s / 131.8s）。这是设计里赌的那一点真的成立了：
献祭点在 `mineRange` 之内，玩家付款全程都在抡锄头砸墙，付满的下一下就是破封。

价格从 150 下调到 **120**。150 是按「Lv4 那一刻 118 + 横扫赏金 46」算的，但同批还改了
锄头 Lv4 的宝石价（6→4），玩家因此更早买到 Lv4、更早触发横扫——而横扫赏金是固定一笔，
手挖得少总收入反而更低。150 的那一版金币归零、献祭那一步涨到 16.4 秒（`ensureProgressAffordable`
在补钱）。降到 120 之后剩 22，献祭步回到 6.1 秒。

| | 改前 | 改后 |
|---|---|---|
| 通关（自动机） | 135.2s | 133.2s |
| 金币余量 | 164（占产出 44%） | 22 |
| 锄头 Lv4 空档 | 35.2s，不解锁任何东西 | 23.5s，解锁封印 |
| 终局最后一个操作 | 站在地贴上付钻石 | 自己抡镐砸开封印墙 |

### 搬走三张贴之后（2026-09-08，三局连跑）

| | 搬之前 | ① | ② | ③ |
|---|---|---|---|---|
| 通关 | 120.9s | 126.9s | 120.5s | 121.8s |
| 破高级矿后最内半径 | **6.4**（回到城里） | **33.5** | **30.7** | **32.0** |
| 破高级矿后路程 | 148m | 89m | 99m | 96m |
| 金币余量 | 23 | 69 | 63 | 54 |

三局的锄头 Lv4、进化、破封全在半径 41 上完成，玩家再没进过半径 30 以内——那趟往返消失了。
总时长在方差内没动（120.5~126.9 对 120.9）。

## 踩到的坑

**看门狗会在破封前那不到一秒里再摆一张 0/120 的新贴。** 判「已经摆过」原先用的是
`zones.some(z => z.id === "seal")`，而 `removeZone()` 会把 zone 从数组里摘掉——付满到破封
之间的窗口里这条判断为假，看门狗于是又摆一张。实测那张贴一直挂到演出里，压在对峙那一拍的
画面上。改成一次性标记 `sealOffered`。

**`guideThroughGate` 会把玩家从城内的地贴上拽走。** 锄头贴改成两个槽位之后，
`getGuideGoal` 里那一行顺手包了 `guideThroughGate`——它要为封印走廊那个槽服务。但同一行
也管着城里那三级，而这个函数的原意是「目标在矿区、玩家在城里，先去谷口」：对城内目标它
返回的是半径 15.5 的谷口，方向和目标相反。

失效过程是会自锁的：玩家被拽离地贴 → 偏角变大 → 绕行判断更不肯松手。实测锄头 Lv2 那张贴
付到 2/4 就再也回不去，整局卡死在城里，`pickaxe:2/4` 挂了 300 秒，玩家在 (5.65,-8.48)
两个点之间来回抖。

修在 `guideThroughGate` 自己身上，不是在调用点加判断：**目标在自由圆里就直接返回。**
其余调用方（矿点、献祭点、炸药桶）的目标本来全在圆外，行为一行不变，而任何以后新增的
城内目标都不会再踩一次。
