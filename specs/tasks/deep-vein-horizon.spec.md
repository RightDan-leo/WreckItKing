# Task: 深层矿脉远景

在封印矿之外再铺几层矿脉，**只给看，不给挖**。目的是让玩家在通关前后意识到「我玩到的只是开头」，为 CTA 那一下服务。

这批矿不进任何玩法数据结构：没有格子、没有碰撞、没有守卫、不掉任何东西、引导不指它、横扫扫不到它、终局判定看不见它。它是一块会动的背景板。

## 能塞几层由相机说了算，不由场地说了算

这件事的全部难点在这里。相机是固定俯视跟随，不是自由视角，所以「远处有东西」不等于「玩家看得见」。

两台相机的参数完全不同，得分开算：

| | 机位高度 | 俯角 | 画面顶边够到的地面 |
|---|---|---|---|
| 常规跟随 | 焦点上方 26 | 53.1° | 玩家前方约 26 |
| 终局对峙 | 约 22 | 34.3° | 相机前方约 101 |

俯视相机有一条硬边界：画面顶边那个平面是斜向下的，越远越低，**低于地面之后那一段地面就不在画面里了**，跟物体多高没关系——长得高只会更早被顶边切掉。常规跟随的这条线落在玩家前方 26 米，而玩家最远只能走到半径 43（封印矿内缘），所以**游戏过程中半径 69 以外的东西，无论多大都不会出现在屏幕上**。

终局对峙那一拍完全是另一回事：机位退到 22 米高、俯角只有 34°，顶边够到相机前方 101 米，换算过去能看到半径 120 左右。而 CTA 的遮罩是个底部渐变，**画面上半截是全透明的**——那正好是这批远景所在的位置。

所以这件事的正确形态不是「在远处堆很多层」，是**两段式**：

- **游戏过程中**：玩家每凿穿一层往前走，就有一层新的远景从画面顶边升起来。看得见的是 2 层。
- **终局对峙 / CTA**：相机退开，一次性把 4 层全露出来，压在巨龙背后。

## 层与层互相挡，所以高度必须是阶梯

俯视角下前一道墙会在后面投出很长一片视觉盲区。盲区的边界是「相机→前墙顶」这条射线，后面那道墙只有高过这条射线的部分才露得出来。

于是每层的高度必须比前一层高，但又不能高过画面顶边。这两条从相反方向夹过来，夹缝随距离迅速收窄——按终局机位算，第 5 层开始射线和顶边几乎平行，缝只剩半米，再往外加多少层都是白加。

**4 层是这台相机的上限**，不是拍脑袋定的数。

| 层 | 半径 | 高度 | 终局机位下可见的高度区间 | 常规跟随下 |
|---|---|---|---|---|
| 封印矿（已有） | 45.2 | 6.2 | — | 玩家贴脸 |
| 深层一 熔岩脉 | 53 | 5.5 | 2.7 → 5.5 | 0.5 → 5.5 |
| 深层二 剧毒脉 | 61 | 6.5 | 2.5 → 6.5 | 1.1 → 4.9（顶被切） |
| 深层三 皇金脉 | 70 | 8.0 | 3.9 → 8.0 | 顶边以外，看不到 |
| 深层四 虚空脉 | 80 | 10.0 | 5.8 → 9.0（顶被切） | 看不到 |

顶被切不是毛病：一道墙高到出画，读起来正是「它比前面几道都大」。

实机量到的终局机位是 `[19.1, 21.6, -11.7]`（半径 22.4、高 21.6），和上面这套推算基本吻合，四层在那一拍里全部露出来。

## 场地边缘要在扇形方向让开

场边那圈岩石（半径 48、高 4~9）正好卡在封印矿和深层一之间。按上面那条射线算，一块 9 米高的石头会把身后到半径 67 的地面全挡死——**深层一和深层二会被自己家的场地边缘挡没**。

所以扇形范围内的边缘岩石要去掉。代价是场地在矿脉方向不再闭合，但这恰恰是想要的读法：**峡谷朝深处敞开，城和两侧仍然被山围着**。扇形以外那 270° 的岩石一块不动，主城那一圈的包裹感不受影响。

两侧岩壁则要顺着延出去，而且越往外越高，把这条深谷框住、顺带挡住地面圆盘的边。延出去的部分**不注册碰撞体、也不投影**：玩家被封印矿内缘卡在半径 43，永远走不到那儿；阴影相机只有 ±40，投出来的影一个像素都落不到画面上。

### 延伸段必须张开，否则它自己就是最大的遮挡

第一版把两侧岩壁沿扇形边线笔直延出去，结果终局那一拍右半屏全是灰石头——**它比刚拆掉的边缘岩石挡得还狠**。原因是终局机位架在扇形边线外侧（实测半径 22.4、方位角 −32°，而扇形边线在 −45°），斜着往里看，那道笔直的长堤正好横在视线上，从相机脚下一路铺到深处。

改成随距离张开（到最深处单边多张 0.42 弧度）。张开之后它退到画框边缘，同时读成「这条谷往深处越走越宽」。四层远景也跟着张，每层比扇形多张 0.05 / 0.12 / 0.2 / 0.28——世界越深越宽，比四条等宽的同心带更像还有得探。

地面圆盘要跟着扩到能兜住最深那层。远处会被雾吃掉大半（`FogExp2` 密度 0.0125，半径 100 处约八成融进背景色），不会看出是一块突兀的大圆盘。

## 视觉必须是升级，不能只是「又一层」

四层同色的话读出来是「后面还有更多一样的东西」，那不构成吸引力。所以每层换一种矿脉，颜色一层比一层稀有，尺寸一层比一层大：

| 层 | 矿脉 | 主色 | 自发光强度 |
|---|---|---|---|
| 深层一 | 熔岩脉 | 暗红底 + 橙红辉光 | 0.40 |
| 深层二 | 剧毒脉 | 墨绿底 + 荧光绿辉光 | 0.50 |
| 深层三 | 皇金脉 | 赭金底 + 金色辉光 | 0.56 |
| 深层四 | 虚空脉 | 深紫底 + 紫罗兰辉光 | 0.64 |

深层一不能取冷色：封印矿是深青，两道墙前后叠着看，同色系分不出层次。

但它必须是四层里最暗的一层，而这是被终局构图逼出来的：**橙色的巨龙正好压在它前面**。第一版按「熔岩就该亮」给到和别层一样的强度，结果龙的轮廓被身后的亮红吃掉，两团暖色糊成一片。压暗之后龙才跳得出来，顺带把整条梯子的方向定死——**越深越亮**，读成「好东西在更里面」。

### 不能半透明

近处矿墙是半透明的（透出里面的金币、宝石、守卫），远景照抄这一条是错的。一层墙有三排格子、顶排还错开，半透明会让它们互相叠加，颜色一路加到发白——第一版四层远景全糊成糖果色的横条，比不加还糟。改成不透明之后层次立刻出来了。

### 每层要有一道更亮的脊线

不透明之后又出现新问题：每层是一条均匀的色带，四条并排读成彩条。把参差的那道顶排单独拆出来、自发光提到 1.75 倍，每层就有了「上缘在发光、下面压在暗处」的厚度，读成矿脉而不是色带。代价是每层两个 draw call 而不是一个。

体素也要跟着变粗。远处的小格子在屏幕上只有几个像素，糊成一片噪点；格子放大之后反而读成「那边的矿石块头更大」。顺带把实例数压下来——四层一共约 500 个实例，比现有矿区（约 1500）轻。

## 里面要冻着更大的东西

「后面内容更多」和「后面敌人更强」是两件事，后者更能拉动下载。每层矿里一到两只剪影，体型逐层放大（1.7 / 2.1 / 2.5 / 3.2 倍），最深那层比它所在的矿墙还高——读起来是 boss 级。

剪影沿用矿内守卫那套造型（方块拼的人形 + 发光眼睛），但有两处必须改：

- **站位压在矿墙的内侧面上**，一半埋进墙、一半探在外面，读成「正在从矿里挣出来」。矿墙不透明了，整只埋进去就什么都看不见；整只站在墙外又成了空地上的散兵，和「这层矿里封着东西」是两句话。
- **眼睛不能照抄 `depthTest: false` 那套 X 光画法**。近处那么做是因为身体隔着四五层矿石会被叠没，只剩眼睛能读，代价是眼睛脱开墙体浮在半空——上次「像光斑」栽的就是这个。远景身体本来就露在外面，不需要透视。

眼睛慢速一呼一吸（1.3 rad/s）。静止的远景会被当成贴图，画面上方有东西在动，视线才会往那边走一次——而那正是这批矿唯一要争取的东西。呼吸走颜色明暗而不是 `opacity`：透明材质要进透明队列排序，逐帧抖动会让眼睛一闪一闪地穿墙。

### 剪影要合批

一只剪影是九个方块加两只眼睛，六只就是 66 个 Mesh、66 次 draw call。为一块背景板付这个价在手机上不合算。同一层的几只共用材质，所以按层攒齐世界矩阵、合成两个 `InstancedMesh`（身体一个、眼睛一个），66 降到 8。

## 不能碰的东西

这批矿只要沾上任何一个玩法结构就会出事，逐条列出来：

| 结构 | 沾上会怎样 |
|---|---|
| `ORE_TIERS` / `TIER_ORDER` | `requiredShardGrade()` 按锄头等级索引 `TIER_ORDER`，多一项就错位；地表色带、装饰石避让也都遍历它 |
| `oreRings` | `playerOuterLimit()` 遍历它找封印层，多出来的环会改玩家边界 |
| `oreNodes` | `getNearestOre()` 会把引导箭头指到走不到的地方；`minableRemaining()` 会认为还有矿可挖 |
| `breachedByTier` | 终局触发条件 |
| `pendingSweepTiers()` | 炸药桶会试图横扫它 |
| `solidColliders` | 白白增加每帧碰撞解算的数量 |
| 阴影 | 平行光的阴影相机只有 ±40、far 90，这批矿全在外面，`castShadow` 开着等于纯浪费 |

做法：单独一张 `DEEP_VEINS` 表 + 单独一个 `createDeepVeins()`，产物只挂 `scene`，不进任何数组。

## 变更范围

| 模块 | 变更 |
|---|---|
| `DEEP_VEINS` | 新增；四层的半径、厚度、高度、张角、格子尺寸、配色、剪影规格 |
| `DEEP_FIELD_RADIUS` | 新增；地面与两侧岩壁要让到哪里，由最深那层推出来 |
| `createDeepVeins()` | 新增；每层两个 `InstancedMesh`（本体 + 脊线）加地表色带 |
| `collectDeepGuard()` / `buildDeepGuards()` | 新增；剪影按层合批 |
| `updateDeepGuards()` | 新增；眼睛呼吸。挂在 `update()` 的非交互段之外 |
| `createOreField()` | 建完四层矿之后调 `createDeepVeins()` |
| `createArena()` | 地面圆盘扩到 `DEEP_FIELD_RADIUS + 4`；扇形内跳过边缘岩石 |
| `createSectorWalls()` | 延伸段随距离张开、逐段抬高；`place()` 的 `collide` 为 0 时不注册碰撞体也不投影 |
| `tuningRoot()` / `__wik.tune()` | 挂上 `DEEP_VEINS` |
| `TUNING_SCHEMA` | 新增一组：四层的半径、高度、剪影体型（都要重载） |

## 验收标准

- [x] 玩家走到封印矿前时，画面上方能看到 2 层走不到的矿脉（熔岩脉整段 + 剧毒脉大半）。
- [x] 终局对峙 / CTA 那一拍，巨龙背后能看到 4 层逐层升高的矿脉。
- [x] 四层颜色和体量一眼分得出递进关系，不读成「同一层重复了四遍」。
- [x] 最深那层里的剪影比它所在的矿墙还高，明显不是玩家打过的那种守卫。
- [x] 引导箭头永远不指向这批矿；横扫不清它；终局照常触发（`breached.sealed = 0`）。
- [x] 玩家走不到它跟前（边界仍由封印矿内缘决定，未改）。
- [x] 两版通关时长与基线一致。
- [x] 竖屏下四层同样露得出来。

## 实测

改动前后各跑一遍 `__wik.sim()`：

| | 金币版 | 宝石版 |
|---|---|---|
| 改动前 | 168s | 140s |
| 改动后 | 168s / 172s | 136s |
| 关键节点 | `18 / 30 / 50 / 70 / 96 / 122 / 158` | `20 / 26 / 44 / 56 / 74 / 84 / 118 / 126` |
| `breached.sealed` | 0 | 0 |
| 地上残留掉落 | 0 | 0 |

金币版改动后第一次跑出来和改动前逐项完全一致（168s，节点一个不差），第二次 172s，落在既有的 167–174s 抖动区间内。这批矿不进任何玩法结构，理论上就该是零影响，实测吻合。

渲染增量：矿墙 8 个 draw call（四层各本体 + 脊线，约 500 个实例）、地表色带 4 个、剪影 8 个、两侧延伸段约 28 块石头，减去扇形内让掉的约 21 块边缘岩石。剪影不合批的话这里会是 66。

## 已知取舍

- **常规跟随下只看得到 2 层，另外 2 层要等终局。**这是相机决定的，不是可以调大的数。真要让 4 层在玩的时候全露出来，只能改俯角或拉远机位，而那会动到整局的手感和已经配平过的终局构图，不值得。
- **深层三、四没有「第一次出现」的时刻。**它们是随终局镜头一次性亮相的，冲击力集中在 CTA 那一拍。如果之后想让它们在玩的过程中也露一次，可以考虑给终局前的某一拍单独抬一次机位。
