# Task: 强化石怪扇形击飞

## 背景与动机

强化石怪原两段方案连续使用两个圆形预警，但两次形状相同、效果不同，玩家难以仅从预警外观判断哪一段会击飞。第二只怪应改为单一、辨识度更高的扇形攻击，让预警形状与击飞效果保持一致。

## 目标

强化石怪显形落地后立即进入战斗，接近玩家后面向玩家蓄力并释放一次宽扇形冲击。扇形命中造成比第一只怪略高的伤害和强击飞，玩家需要横向离开扇区。所有伤害只在扇形预警结束时结算，身体接触不造成伤害；本任务不修改玩家自动攻击目标切换规则。

## 已确认设计

### 扇形击飞

- 强化石怪进入约 `3.6` 单位攻击范围后停止移动，面向玩家并抬起双臂。
- 以怪物脚下为扇形原点，显示朝向玩家的红色扇区预警。
- 默认扇形半径约 `4.5` 单位，夹角约 `100°`。
- 预警总时长约 `0.8s`。
- 前 `0.35s` 持续转向玩家，之后锁定扇形方向，为玩家保留横向躲避窗口。
- 结算时只检测玩家是否处于扇形半径和夹角内。
- 命中造成约 `10` 点伤害，并沿扇形方向将玩家击飞约 `3.2` 单位。
- 攻击结束后进入约 `1.2s` 收招，提供稳定输出窗口。

### 通用规则

- 强化石怪只有这一种攻击，不再生成圆形地裂预警。
- 身体接触不造成伤害。
- 每一段伤害都必须由可见预警结束后触发。
- 怪物死亡或攻击失效时清理尚未结算的预警。
- 玩家可在强化石怪蓄力和收招期间继续攻击。
- 不新增吼叫。
- 不修改玩家自动攻击切换、矿墙目标或阶段推进规则。

## 配置

在 `MINE_DEFAULTS["mine-strong"].combat` 集中维护：

- `speed`
- `attackRange`
- `windupDuration`
- `trackDuration`
- `sectorRadius`
- `sectorAngleDegrees`
- `damage`
- `knockback`
- `recoveryDuration`

`cloneMineConfig()` 必须合并默认值并将所有字段规范化为数值。

## 状态流转

1. `dormant`：位于矿墙剪影阶段。
2. `chasing`：接近玩家，身体接触无伤害。
3. `windup`：持续转向后锁定方向，双臂蓄力并显示扇区预警。
4. `recovery`：扇形结算后的稳定输出窗口。
5. `dead`：沿用现有死亡、掉币和龙蛋阶段推进。

## 变更范围

- `WreckItKing.html` `MINE_DEFAULTS["mine-strong"]` 与 `cloneMineConfig()`：配置扇形攻击。
- `WreckItKing.html` `createGolem()`：保存强化石怪扇形状态和配置。
- `WreckItKing.html` `updateEnemies()`：把强化石怪路由到独立扇形攻击状态机。
- `WreckItKing.html` hazards：增加扇区几何预警、方向锁定和扇形命中检测。
- `WreckItKing.html` 强化石怪动作：双臂蓄力、冲击和收招复位。

## 验收标准

- [x] 强化石怪显形落地后能够主动接近玩家并开始扇形攻击。
- [x] 游戏中不再出现强化石怪的圆形攻击预警。
- [x] 扇形预警朝向与实际伤害、击飞方向一致。
- [x] 玩家位于扇形外或锁定后横向离开时不会受伤。
- [x] 玩家位于扇形内时受到约 `10` 点伤害和 `3.2` 单位击飞。
- [x] 身体接触不造成伤害。
- [x] 攻击结束后存在约 `1.2s` 的稳定输出窗口。
- [x] 怪物死亡或离场后不残留扇形预警。
- [x] 原有龙蛋掉落和后续阶段推进保持不变。

## 风险与注意事项

- 扇形几何的可视角度必须与命中检测使用同一个角度配置，避免“看起来躲开却被击中”。
- 预警锁定后不得继续旋转，否则玩家无法通过横向移动躲避。
- 击飞距离需要传入 `damagePlayer()` / `pushPlayerAwayFrom()`，不能影响 Boss 和第一只石怪的默认击退距离。
- 强化石怪必须绕开普通敌人的旧攻击冷却分支，避免额外生成旧版圆形 hazard。
- 预警跟随时间不得覆盖全部蓄力时长，必须保留可躲避的锁定窗口。
