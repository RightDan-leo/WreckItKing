# Task: 金币无条件自动回收

## 目标

金币从哪儿产出——挖矿、打怪、爆炸——都自己飞回玩家背上，玩家永远不需要走过去捡。爆炸那一下要看得出「赚了一大笔」。

## 问题：8.5 米之外的金币等于没掉

改之前 `updateCoins()` 里的 `idle` 分支是这样判的：

```
distance < coinCollectRange(2)  → 起飞回背上
distance < coinMagnetRange(8.5) → 朝玩家滑过去
否则                             → 永远躺在地上
```

半径之外的金币不会消失，也不会回来，就那么躺着，直到玩家碰巧走近。三条产出路径里有两条经常落在半径外：

- **打怪**：宠物会自己脱队去追怪。它在十几米外打死的怪，掉的金币玩家根本收不到。
- **爆炸**：横扫沿整道矿墙铺开，最远的柱子离爆点十几米。

这也是为什么横扫当初得自己写一个 `vacuumCoins()`——它绕开 `dropCoins`，让金币直接以 `toBack` 状态出生。那是给症状打的补丁：真正的毛病是回收有半径限制，而不是横扫特殊。**本次改动删掉了 `vacuumCoins()`，三条路径合回同一条 `dropCoins()`。**

## 统一的生命周期

```
toss（抛物线崩出来）→ 落地 → idle（停 coinDwell 一拍）→ toBack（飞回背上）
```

三段都不判距离。

**为什么保留落地后那一拍（`coinDwell = 0.16`）**：没有它，金币在抛物线顶点就被吸走，「这东西是从这儿崩出来的」还没传达完就没了。挖矿一锤下去要看得见金币从矿面上迸出来，而不是凭空出现在背上。

**为什么飞行时长按距离算**：`0.26 + distance * 0.026`，夹在 0.26–0.8 之间。固定值两头都不对——0.3 秒放在 20 米外是一道残影，0.8 秒放在脚边是一枚慢吞吞飘过来的金币。抛物线高度 `1.1 + distance * 0.1`（上限 3.6）同理，近处平飞、远处走高弧。

**为什么用缓入曲线**：位置插值用 `t²` 而不是线性。起步慢、末段猛地窜进背上，读起来才像被吸走；匀速直线只是「在移动」。

## 爆炸：密度决定「一大笔」，而密度不能由经济数值决定

横扫的赏金是固定的 18（低级）/ 30（中级）枚，这个数不能动——[pickaxe-upgrade-sweep](pickaxe-upgrade-sweep.spec.md) 里算过，按残矿实际产出结算会白送整局 89% 的经济。

但 18 枚金币在固定俯视镜头下就是十几个零星小亮点，完全撑不起「赚了一大笔」。

### 影子金币

`dropCoins(pos, count, { ghostRatio })` 额外生成 `count * ghostRatio` 枚**只有视觉、不进账**的金币。它们照常抛出、照常飞回背上，但到达时不加金币数、不发声、不顶 HUD。横扫用 `ghostRatio: 2.5`，于是 18 枚赏金在画面上是 63 枚金币的洪流，而经济一分没变。

计数器和音阶必须只跟真实收入走，否则玩家听着音阶爬了三十级、数字只跳了十下，反而露馅。

影子金币不投影（`castShadow = false`）：横扫时场上会顶到 `maxCoinDrops` 上限，一百多个投影体在移动端是实打实的开销，而这一枚本来就只是充数的。

`ghosts` 的数量在分配前先被剩余名额夹一次，真实金币永远优先占位，不会被影子挤掉。

### 抛射要低、要窄、要快

第一版给了 `burst: 1.9` / `spread: 2.4`，金币被甩到七八米高、铺满整段弧。实机截图下那是一地互不相干的小亮点——散开就是把密度做没了。现在是 `burst: 1.1` / `spread: 1.3` / `dwell: 0.02`：贴着地炸开，几乎不停顿就连成一条流冲回背上。

### 出生点从波前往爆点收回一半

矿墙横跨约 30 米，竖屏只框得下 35 米左右。严格贴着波前生成的话，弧两端炸出来的金币直接落在画框外，玩家看到的只有零星几枚。`lerp(波前柱, sweep.origin, 0.5)` 之后金币仍然是从塌陷的方向来的，但全都落在镜头中心附近。

## 钻石：同一条流水线，相反的调法

守卫掉的钻石走的是同一个 `dropCoins`，但要读出来的东西和金币相反。金币讲「一大笔冲回背上」，所以调法是抛得低、散得窄、几乎不停顿，让它连成一条流；钻石一次只有四到八颗、每一颗都对着一次具体的武器或宠物升级，讲的是「打完了，地上散着几颗，然后被收走」——三拍里**中间那一拍必须看得见**。

### 病根是三拍重叠，不是躺得不够久

原先的参数是 `burst: 1.3` / `spread: 1.6` / `stagger: 0.06`，没给 `dwell`，吃 `CONFIG.coinDwell` 的 0.16。用 `__wik.drops()` 逐帧量高级守卫（八颗）：

| 指标 | 实测 |
|------|------|
| 总时长（掉出 → 全部入账） | 1.98s |
| 有钻石在空中 | 0.97s |
| **至少有一颗**躺在地上 | 0.85s |
| **八颗全都**躺在地上 | **0.05s** |

「至少有一颗在地上」有 0.85 秒，不算短——所以第一直觉「停顿太短，加 dwell」是错的。真正的毛病在最后一行：分段之和 0.97 + 0.85 + 0.95 = 2.77 秒被挤进 1.98 秒的总时长里，说明**任一时刻总有几颗在空中、几颗在地上、几颗已经在飞回去了**。「一地钻石」那一拍实测只有 0.05 秒，等于从没出现过，于是整段被眼睛读成一条连续的喷泉接吸走，而不是「掉了一地，然后被收走」。

重叠是两个随机量叠出来的：出生高度（`1.4 + 0.4~1.2`）和抛射初速（`(4.2 + rand*2.8) * burst`）让落地时刻散布在 0.6~1.0 秒；而起飞时刻是 `dwell + rand * stagger * 颗数`，八颗时额外滞留 0~0.48 秒。第一颗起飞（0.6 + 0.16 = 0.76s）比最后一颗落地（1.0s）还早，窗口自然是负的。

### 三个数一起动才拆得开

拆开重叠的条件是「最后一颗落地时，第一颗还没起飞」，所以必须同时压落地散布、拉长滞留、收紧起飞错峰：

| 参数 | 改前 | 改后 | 作用 |
|------|------|------|------|
| `burst` | 1.3 | 0.85 | 抛得低，滞空 0.97 → 0.77s，落地时刻也更集中 |
| `dwell` | 无（0.16） | 0.8 | 躺够久，久到最后一颗落地时第一颗还没起飞 |
| `stagger` | 0.06 | 0.02 | 起飞近乎同步，八颗一起被吸走而不是拖成尾巴 |
| `spread` | 1.6 | 2.6 | 补偿：`burst` 同时管纵向和横向，抛低了横向甩距也缩 |

`spread` 只改出生点的水平偏移，不改速度——**散开的活从「抛得更远」交给了「出生点更铺开」**，这是保住散开程度的同时把滞空压下来的唯一办法。实测落点包围盒不变（5.6 米上下）。

扫过的四组参数：

| 配置（burst / dwell / stagger） | 总时长 | 滞空 | 至少一颗在地 | 全都在地 |
|------|--------|------|--------------|----------|
| 1.3 / 0.16 / 0.06（改前） | 1.98s | 0.97 | 0.85 | 0.05 |
| 1.0 / 0.6 / 0.06 | 2.32s | 0.80 | 1.20 | 0.50 |
| 1.0 / 0.8 / 0.03 | 2.17s | 0.88 | 1.08 | 0.70 |
| **0.85 / 0.8 / 0.02（采用）** | **2.10s** | 0.77 | 1.07 | **0.73** |
| 0.85 / 1.0 / 0.02 | 2.37s | 0.80 | 1.32 | 0.83 |

采用第四组：总时长和改前基本齐平（1.98 → 2.10s，不拖节奏），却把「全都在地」从 0.05 买到 0.73 秒。最后一组能到 0.83 秒，但总时长要涨到 2.37，不值。

三个档位都验过，节拍一致（低 4 颗 / 中 6 颗 / 高 8 颗，全都在地分别 0.73 / 0.72 / 0.73s）——`stagger * 颗数` 会随掉落数缩放，所以低级档不会因为颗数少而失去这一拍。

### 撞色：钻石被自己的尸体碎块盖住

做出这一拍之后实机截图才发现另一半问题：守卫一死，`buildDeathDebris` 会喷十四块 `tier.chunkColor` 的碎石，寿命 1.1~1.6 秒——**正好完整覆盖钻石躺地的那 0.73 秒**。低级档尤其糟，碎块 `0x37d7a1` 和钻石 `0x5fe6ff` 同属青色系，而低级档正是玩家第一次见到钻石的地方（中级紫 `0x8a54ee`、高级橙 `0xff7a3c` 都不冲突）。

颜色不能动：钻石的青要和 HUD 的货币图标对上，换色等于换货币身份。所以靠体积拉开——碎块是 0.22~0.46 的小方块，钻石从 0.85 抬到 1.15。

顺带修了一处遗漏：`mesh.scale.setScalar(shard ? 1.2 : 0.85)` 旁边那句「大一号才认得出来」的注释讲的是矿石碎片，钻石一直留在金币的 0.85——同样的理由适用于它，只是当时没写进去。

## 到账反馈

三层，都挂在真实金币上：

**音阶爬升**。`playSound(type, pitch)` 新增频率倍率。连续到账时音高一级级往上推（`1 + min(chain, 16) * 0.052`），断 0.35 秒归零。零散挖矿永远停在最低音，只有成批进账才爬得上去——同一个「叮」重复二十遍是噪音，音阶才读得出「越拿越多」。发声按 0.045 秒节流，否则一次横扫会同时堆出几十个振荡器。

**HUD 顶一下**。`#coin-hud.pop` 每次数字跳动重放一次 0.22 秒的缩放。连着进账时这一下会不停被打断重放，读起来就是「还在涨」。必须 `void offsetWidth` 强制回流，否则同一帧摘掉再加上 class 会被浏览器合并成「没变过」，动画不重放。

**结算数字**。横扫结束时在爆点打出 `+18` / `+30`（`showDamage` 新增 `variant` 参数走 `.damage.gold`）。金币是一枚枚飞回来的，中途没有任何地方说清这一炮到底赚了多少，需要一个明确的数字落点。它的 keyframes 跑 1.15 秒，移除定时器相应从 760 毫秒放宽到 1200，否则会被拦腰截断。

## 接口变更

| 模块 | 方法/属性 | 类型 | 说明 |

| Coins | `launchCoinToBack(coin)` | 新增 | 按距离算飞行时长与弧高，统一所有产出路径的起飞 |
| Coins | `coin.ghost` | 新增 | 只有视觉、不进账的金币 |
| Coins | `registerCoinPickup(elapsed)` | 新增 | 音阶连击 + HUD 顶一下 |
| Coins | ~~`vacuumCoins(pos, count)`~~ | 删除 | 回收无半径限制后，横扫直接用 `dropCoins` |

| Probe | `__wik.drops()` | 新增 | 每颗掉落物的 `kind` / `state` / `dwell` / 坐标，用来量三拍各占多久 |
| Tuner | 「移动与金币手感」 | 修改 | 新增钻石的 `dwell` / `burst` / `spread` 三个滑杆 |

| UI | `ui.coinHud` | 新增 | 缓存 `#coin-hud`，用于重放顶一下动画 |

- [x] 十八米外打死的怪掉的金币会自己飞回来（实测 9 枚全部到账，耗时 1.75 秒，玩家全程站着不动）。

## 待办：通关时长

改动后 bot 三次样本稳定在 169–170 秒（改动前 133 秒）。已与用户确认**先把功能做完，通关时长最后统一调**，因此本次不做补偿性回调。调的时候注意这次改动确实放宽了收入——以前落在 8.5 米外的金币是彻底损失的，现在一枚不丢。
