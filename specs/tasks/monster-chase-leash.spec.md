# Task: 三类怪物追击范围与返回原位

## 目标

为普通石怪、强化石怪和 Boss 统一增加以显形位置为中心的战斗领地。玩家把怪物引出领地，或怪物自身到达领地边界时，怪物取消尚未结算的攻击并返回原位；玩家重新进入较小的重激活范围后，怪物恢复追击。

## 统一规则

- 怪物显形并正式激活时记录 `homePosition` 和初始朝向。
- 追击范围始终以固定 `homePosition` 为中心，不能随怪物移动。
- 玩家离开 `chaseRadius`，或怪物到达 `chaseRadius` 边界时，进入 `returning`。
- 进入 `returning` 时立即清除该怪物尚未结算的圆形、扇形或 Boss 攻击预警。
- 返回期间怪物不追击、不蓄力、不造成接触伤害。
- 怪物按 `returnSpeed` 返回原位，抵达后进入 `leashed` 等待。
- 玩家进入 `reengageRadius` 后恢复追击；该半径必须小于追击半径以避免边界抖动。
- 返回和等待不会恢复怪物生命值，也不会从玩家目标列表移除怪物。
- 怪物死亡后沿用现有掉落与阶段推进，不执行返回。

## 默认范围

- 普通石怪：`chaseRadius = 7`、`reengageRadius = 6.5`、`returnSpeed = 2.2`。
- 强化石怪：`chaseRadius = 10`、`reengageRadius = 9.25`、`returnSpeed = 2.4`。
- Boss：`chaseRadius = 11`、`reengageRadius = 10`、`returnSpeed = 1.9`。

三个范围分别适配首矿、强化矿和 Boss 战场的空间大小。

## 状态

1. `active`：执行怪物原有追击与攻击状态机。
2. `returning`：取消攻击并返回 `homePosition`。
3. `leashed`：停在原位等待玩家重新进入范围。
4. `dead`：不再更新追击范围。

## 配置与接口

- 在三类怪物对应 `combat` 配置中维护 `chaseRadius`、`reengageRadius`、`returnSpeed`。
- `cloneMineConfig()` 分别规范化普通石怪、强化石怪和 Boss 的追击配置。
- `beginEnemyReturn(enemy)`：取消 pending hazards、复位攻击动作并切换返回状态。
- `updateEnemyLeash(enemy, dt)`：统一处理越界、返回、等待和重激活；返回 `true` 时跳过怪物原攻击 AI。
- `cancelPendingHazardsFrom(enemy)`：复用现有预警清理能力。

## 差异化交接

- 普通石怪重激活后进入 `chasing`，继续使用断镐重砸。
- 强化石怪重激活后进入 `chasing`，继续使用扇形击飞。
- Boss 重激活后恢复现有 Boss 追击和预警攻击。
- 三类怪物返回时都清除当前攻击姿态；普通和强化石怪双臂恢复待机。

## 实施计划

- [x] 为强化石怪和 Boss 增加追击范围配置，保留普通石怪现有数值。
- [x] 在三类怪物正式激活时记录固定原位与朝向。
- [x] 抽取共享越界、返回、等待和重激活逻辑。
- [x] 进入返回状态时清理各类 pending hazards。
- [x] 将普通石怪现有返回逻辑迁移到共享系统。

- [x] 将强化石怪追击半径扩大到 `10`、重激活半径扩大到 `9.25`。

## 验收标准

- [x] 三类怪物都只在各自 `chaseRadius` 内追击和攻击。
- [x] 越界时未结算攻击立即取消，不会在脱战后命中玩家。
- [x] 三类怪物能返回各自显形原位并停止攻击。
- [x] 玩家位于领地外时怪物不会在边界反复来回。
- [x] 玩家重新进入 `reengageRadius` 后怪物恢复对应攻击方式。
- [x] 返回不会回血，也不会重复生成或重复加入目标列表。
- [x] 原有断镐、扇形击飞、Boss 战和阶段推进保持正常。
- [x] 强化石怪一次 `3.2` 单位击飞通常不会直接触发脱战返回。

## 第二轮：守卫「一步都追不出去」

反馈是「野怪很容易就脱离战斗，没有威胁」。截图里那只是高级守卫（橙色人形，
`0xc2542c`、scale 1.18），不是走廊里的游荡怪——两者代码分开，上一轮给游荡怪做的提速
（见 `corridor-rovers.spec.md`）没有作用到守卫身上。

### 根因不是「范围小」，是攻击动作比拴绳窗口长

实测：把玩家放在高级守卫 3.2 米处，等它起手，然后径向往内全速跑 10 秒。

| 时刻 | 守卫离家 | 玩家离守卫出生点 | 守卫状态 |
| --- | --- | --- | --- |
| 0.03 s | 0.06 m | 7.5 m | recovery |
| 0.43 s | 0.06 m | 10.7 m | recovery |
| 0.63 s | 0 m | 12.6 m | chasing（已被拽回家） |
| 10 s | 0 m | — | — |

十秒里它离家最远 **0.06 米，一步都没追出去过**。

算一下就知道这是结构性的，不是数值偏小：

- 高级守卫前摇 0.8 + 后摇 1.1 = 一个攻击循环 **1.9 秒**，这段时间
  `updateMonsterCombat` 不移动。
- 玩家 9.4 m/s，从攻击距离 3.7 米跑到当时的 `chaseRadius` 11 米只要
  `(11 − 3.7) / 9.4 = 0.78` 秒。

**它挥完一刀，人已经出圈了。** 于是每次都是「起手 → 玩家跑 → 后摇里被拴绳判定越界 →
returning」。低、中两档同理（循环 1.25 / 1.55 秒，玩家跑 11.75 / 14.6 米，
而 `chaseRadius` 只有 9 / 10）。

三种单点修法都不成立，得记下来免得再试：

- **只提速**：提速只作用在 chasing 分支，而它整个逃跑窗口都在 recovery 里，没用。
- **只在后摇里不判拴绳**：等它能动时玩家已经在 20 米外（3.2 + 9.4 × 1.9），
  照样越界，没用。
- **只放大 `chaseRadius`**：能追了，但原速 2.8 对玩家 9.4 慢三倍多，追不上。

所以必须**同时**放大领地和提速。

### `chaseRadius` 和 `reengageRadius` 原先几乎相等

9 / 8.2、10 / 9.2、11 / 10——两个数只差 0.8 ~ 1，等于没有滞回，玩家在边界上走两步
就能让守卫反复进出战斗。这两个数职责不同，本来就该拉开：

- `reengageRadius` = **多近会醒**（仇恨触发），保持原值不动。
- `chaseRadius` = **追多远放弃**（脱战距离），按「玩家一个攻击循环跑的距离」重新定。

新值取在那个距离上下：低 `14`（玩家一循环跑 11.75）、中 `16`（14.6）、
高 `18`（17.9）。

### 主城禁区

放大领地之后多了一个新风险：低级守卫出生在半径 18.5，主城满级 14.6，中间只隔 3.9 米，
它能一路挤进城里站在地贴上——而「不能有建筑或怪挡住玩家进出主城、和地贴交互」
是城市布局那条定死的约束。

`constrainEnemy` 里加一道硬地板 `cityKeepOutRadius()`：怪的半径不得小于
「主城当前外沿 + `GUARD_CHASE.keepOutMargin`」。按**当前**城级算而不是满级半径——
开局城只有 6.6 米，按 14.6 划禁区会把低级守卫挡在它自己那圈矿的门口。

这里是**位置钳制而不是脱战**：怪贴着城沿等着，玩家一出城战斗立刻接上，
读作「追到地盘边上」。真正的放弃仍然交给 `updateEnemyLeash` 的距离判定。

### 顺带修掉的一处配置漂移

`__wik.tune()` 和调参面板的 `tuningRoot()` 原先各写一份配置清单，已经飘了：
前者有 `ECON`、后者有新加的 `GUARD_CHASE`。于是新增配置在其中一处必然是隐形的
（面板里拖不到，或者探针里读不到），而且两种都不报错。现在 `tune()` 直接返回
`tuningRoot()`，只剩一张表。

### 接口

| 名字 | 作用 |
| --- | --- |
| `GUARD_CHASE.speed` | 守卫激怒后的速度倍率（乘在 `ORE_TIERS[].monster.speed` 上），`2.4`。拖到 1 就是改动前的原速。 |
| `GUARD_CHASE.keepOutMargin` | 主城外沿再往外留多少米的禁区，`0.8`。 |
| `chaseSpeedOf(enemy, config)` | 按 `userData.type` 分派倍率：`rover` 用 `ROVER_RANGE.chase`，`monster` 用 `GUARD_CHASE.speed`，巨龙不乘。 |
| `cityKeepOutRadius()` | 主城当前外沿 + margin；`cityLevel` 为 0 时返回 0（还没建城，没有安全区）。 |
| `constrainEnemy(enemy)` | 追加主城半径下限钳制。 |

### 实测结果

| 项目 | 改动前 | 改动后 |
| --- | --- | --- |
| 高级守卫追出的距离 | **0 m**（一步没动） | 7.9 m |
| 甩掉它要跑多远 | 走开即可 | 18.8 m |
| 完整一局用时 | — | 130.8 s |
| 全程最低血量 | — | 43 |
| 守卫进城 | — | 1834 次采样，**0** 次 |
| `?arpg=0` 完整一局 | — | 127.5 s，最低血量 65，0 次进城 |

游荡怪回归检查（`chaseSpeedOf` 重构后）：从半径 22.8 追到 17.63 后返回，
和 lane 内缘 20.7 减去 `tether` 3 米算出的 17.7 一致，行为未变。

## 风险与注意事项

- 追击范围检查应先于 stagger、frozen 和攻击状态，避免怪物因受击或蓄力卡在边界外。
- 重激活时只恢复 AI 状态，不能重置 HP、掉落或显形状态。
- Boss 的 `homePosition` 必须取正式 Boss 生成位置，不使用已移除的剪影预览对象。
- 返回移动仍需经过现有 arena 限制。
- `chaseRadius` 改小到玩家一个攻击循环跑的距离以下，就会退回「一步都追不出去」那个
  状态。这两个数是耦合的：调前摇 / 后摇也要回头看这里。
- `reengageRadius` 不要跟着 `chaseRadius` 一起放大。低级守卫出生在 18.5，
  仇恨半径给到 19 就等于整座主城都在它的唤醒范围内，玩家会被永久追着。
