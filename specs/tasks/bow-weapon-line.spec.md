# Task: 武器线改成弓箭

> **这份 spec 是交接件。** 需求和前期调研在经济/节奏那条线上做的，实现归 ARPG 战斗改造那条线——
> 弓箭长在 `playerAttack` / `WEAPON_LEVELS` / `applyWeaponAppearance` 上，那是战斗改造的地盘。
> 下面记的是需求原文、已经拍板的设计决定、量过的数，以及一个**必须先解决的结构性风险**。

## 需求（用户原话，2026-09-07 17:02）

> 把武器升级从锄头改为升级弓箭。现在升级了锄头的攻击效果后，其实体感不明显。新的预期是：
> 升级武器，可以让弓箭越来越强，打出越来越炫酷的特效造成伤害。并且第一次升级武器应该在
> 建造孵化台之前。另外啊一边升级锄头：锄头的挖矿效率越来越高，速度越来越快。能解锁高级矿。

最后一句（锄头只管挖矿）**现在已经是这样了**，不用改。切分在 `WEAPON_LEVELS` 上面那段注释里，
锄头吃宝石管 `power`，武器吃钻石管伤害。

## 这条反馈命中的是一条已知代价

不是设计漏了，是当初权衡时明写下来接受的：

```js
// 不新增手持物。四级都是给手上那把镐附魔（见 applyWeaponAppearance），
// 一是模型和挥击动画都不用动，二是免了「矿工背着剑挖矿」的违和。
// 代价是「升武器」和「升锄头」在玩家眼里都是升镐子，靠地贴的名字和图标区分
// （锻造台 + 火焰，对锄头台的镐子图标）。
```

实机验证下来这个代价太贵：两条线花的是两种货币、买的是两种东西，玩家看到的却是同一把镐子
亮了一下。现在决定付钱把它做对。

## 已拍板的设计决定

### 1. 手持物随目标切换

打矿举镐、打怪举弓。这一下本身就把两条线彻底分开了，比靠地贴图标区分强得多，而且不动任何数值。

`playerAttack()` 里已经有 `const mining = target.userData.type === "ore"` 这个分叉，切换挂在这儿最省。

### 2. 距离：抬到中程 6~7 米（**用户选的，但有坑，见下一节**）

当前：玩家 `CONFIG.attackRange` 4.4，三档守卫 2.4 / 3.0 / 3.7。

### 3. 分级特效挂在已有字段上，数值一个不动

`WEAPON_LEVELS` 现有的 `reach` / `splash` / `splashRatio` 正好够用，伤害数列
235 / 425 / 615 / 805 原样保留——**七只守卫的血量因此一格都不用重调**。

| 级 | 现有字段 | 建议表现 |
|---|---|---|
| Lv1 | reach 0，splash 0 | 素箭 |
| Lv2 | reach 0.6 | 带拖尾，射程加长（这 0.6 米现在玩家根本感觉不到，做成箭矢飞行距离才看得见） |
| Lv3 | splash 2.6 / ratio 0.3 | 三连击第三箭命中炸开 |
| Lv4 | splash 3.4 / ratio 0.55 | 炸得更大更亮 |

三连击（`attackSequence`）和第三下的加重（独立音效、更大弧光、更重震屏）是现成的节奏点，
箭矢版本要继承，别磨平。

### 4. 锻造台提前到孵化台之前

用户明确要求。这会**推翻 `completeHatchery()` 里那条明写的决定**：

```js
// 锻造台在孵化之后才亮。钻石有三个出口（孵化 8、进化 14、武器 18），
// 它们抢同一个池子，而龙是这个广告的卖点——宠物线必须排在前面，
// 不能让玩家在见到蛋之前就把钻石花在一条可选支线上。
```

代价是第一级弓箭那 4 颗钻石插在孵化前面，龙晚出来几秒。判断是值得：弓箭正是让战斗好玩的
那个东西，来太晚就没意义。实测两者现在只差 5~10 秒（孵化 48~55s，锻造 55~65s），挪动很小。

建议的新触发点：**第一次拿到钻石时**（也就是打死第一只守卫的那一刻）。它把「钻石从哪来 →
钻石买什么」直接连成一句话，比挂在城等级上更说得清。

## 必须先解决的风险：中程会把问题反过来

> **已解掉，见文末「实现结果」。** 走的是下面的补法 1（给守卫够得着的招），不是补法 3。
> 下面这段推演保留原样——它把「为什么必须补」算清楚了，是那三件补法的依据。

**这一条是这份 spec 里最要紧的。**

ARPG 那章的题眼是：躲避在数值上是亏的，站桩硬吃才是最优解，所以要把代价和收益换成秒数。

抬到 6~7 米之后，最优解会从「站桩硬吃」翻成「**风筝**」，而这同样让闪避、破绽、狂暴全部失效——
只是换了个方向失效：

- 玩家射程 6.5，守卫攻击距离最远 3.7，**净出手距离差 2.8 米**
- 守卫移动速度 2.4~2.8（`GUARD_CHASE.speed` / `ORE_TIERS[].monster.speed`），玩家 `playerSpeed` **9.4**
- 速度差 3.4 倍、距离差 2.8 米 → 守卫永远进不了自己的攻击距离，玩家零风险输出

也就是说，**不给守卫一条够得着远程玩家的路，中程弓箭等于把战斗关掉**。

可选的补法（没验过，交给实现方判断）：

1. **给守卫远程或突进招**。招式池 `ORE_TIERS[].monster.moves` 已经是数据驱动的，加一招
   冲锋或投射物是这套结构本来就支持的，也最对味——「它急了所以扑上来」比「它跑得更快了」好读。
2. **起手瞬间拉近**。守卫进入 windup 时向玩家方向位移一段，把 2.8 米差值吃掉。改动最小。
3. **压回中程的下限**。5.0~5.5 而不是 6~7，让差值只有 1.3~1.8 米，配合已经放大的
   `chaseRadius`（14 / 16 / 18）也许还兜得住。最保守。

无论走哪条，**改完必须重测「硬吃 vs 躲避」的 DPS 差**——那是 ARPG 那章的验收核心，
现在这条改动直接冲着它去。

## 实现结果

### 风筝那条风险：解掉了，而且反过来了

上面「必须先解决的风险」担心的是抬到中程之后最优解从站桩翻成风筝。走的是补法 1
（给守卫够得着的招），没走 3（压回下限）——射程最后定在 `CONFIG.attackRange` 4.8，
加上 `nearestTarget()` 本来就有的 1.4 米余量，实际交战距离 6.2，正好落在用户要的 6~7。

三件事一起才拦住风筝，少一件都不够：

1. **招式自带 `reach`**（中级冲锋 8、高级 9）。原先所有招式共用 `attackRange`，
   守卫在 3.7 米外根本不起手，风筝的人永远不会被冲。
2. **`GUARD_CHASE.patience` = 0.8 秒**。追不上就换远程招——没有这条，守卫会一直
   老实追，永远追不到。
3. **长条按玩家的后退量动态加长**（`ARPG.chargeRetreatCover` = 0.9）。原先长度写死
   9.5/11，玩家一边看预警一边往后退就出圈了；现在长条会盖住前摇里能退到的地方，
   **往后退躲不掉，只能侧移**。

四种打法各打一只满血高级守卫（武器 Lv1，每局重载保证守卫满血、玩家满血）：

| 打法 | 耗时 | 掉血 | 被命中 | 触发冲锋 |
|---|---|---|---|---|
| 贴身躲避 | **22.2 秒** | **53** | 5 | 8 |
| 站桩硬吃 | 28.8 秒 | 85 | 11 | 7 |
| 中程 + 侧移 | 53.2 秒 | 83 | 7 | 16 |
| 纯风筝 | 93.8 秒 | 85 | 10 | 16 |

**贴身躲避在两个轴上同时最优**，纯风筝在两个轴上同时最差（慢 4.2 倍还照样掉满血）。
这比 ARPG 那章的目标更进一步：那儿只要求躲避不亏，这儿躲避是明确的最优解。

> 测的时候踩了两个坑，写下来免得重犯：**一局一次页面重载**。同一次加载里连着打，
> 溅射和仇恨会把隔壁守卫也打掉血（实测第二只被打到 7355/9000），下一局就从残血开始，
> 报出「2.6 秒打死 9000 血」这种数。另外每局开打前要 `w.heal()` 并把人 `w.tp()` 到
> 固定距离——不然计时里混着几十米赶路，风筝那局因为一直后退赶得更久，看着像「风筝更慢」，
> 其实慢的是路上。

### 完整局（含战斗口径）

五局，全部走到终局演出，武器都升满 Lv4，全程零报错零警告：

| | 值 |
|---|---|
| 通关 | 141.8 / 123.8 / 131.6 / 133.5 / 135.3 秒（基线 130.3 / 135.3 / 160.5） |
| 最长空档 | 12.0 / 13.7 / 11.7 / 13.3 / **15.4** 秒（基线 10.8 / 12.0 / 13.4） |
| 中位空档 | 5.7~6.5 秒（基线 3.5~3.6） |
| 最低血量 | 36 / 64 / 72 / 15 / — （下限 15，够不着死） |
| 闯城 | 0 |
| 结余 | 金币 24~44、钻石 4、高级宝石 13 |

通关时长的跨度从 30 秒收到 18 秒，全部落在 2~4 分钟里。

**空档这一项没有干净通过，如实记下来：** 验收写的是「最长空档不超过基线的 13.4 秒」，
五局里四局在线内（11.7~13.7），第五局 15.4 秒超了两秒。中位空档也整体从 3.5 抬到了 6 秒左右。
方向是清楚的——战斗变长了（要躲、要侧移，不再是站着对砍），挖矿那段的密度没跟着变，
所以"两次事件之间"自然被拉开。这是这条改动的结构性后果，不是抖动。要压回去得动挖矿侧的
节奏（`cellsPerCoin` 或矿量），那是经济线的地盘，留给调通关时间那一轮一起做。

武器 Lv2 落在 **9.7 / 10.4 秒**——打死第一只守卫就买得起，稳定排在孵化（44~53 秒）前面，
用户那条「第一次升级武器应该在建造孵化台之前」是满足的。

钻石对账两版都是余 4，和 `ECONOMY_PRESETS.gem` 里记的账一致：
ARPG 开 → 供给 26+18=44、支出 8+14+18=40；`?arpg=0` → 供给 26、支出 8+14=22。

### `?arpg=0` 回滚

没有 git，回滚就是这个开关，实测干净：`weapon.on` false、锻造台不出现、
守卫钻石掉落退回基础的 3/4/4（共 26，多发的 18 一起消失，不会留下花不掉的余额）、
90 帧里手上一直是镐、弓从不显示。

### 过程中修掉的两个 bug

两个都是「数值上全对、画面上不对」，靠读值发现不了，也靠看截图定位不了——
得先用探针把「应该在哪」算出来，再拿这个坐标去截图里核。

**1. 射程边缘上手持物每秒翻一次。** `update()` 里原先无条件
`setHeldItem(target && ... ? "bow" : "pick")`。守卫在射程边缘被击退推出去、自己再走回来，
一进一出 `nearestTarget()` 就返回一次 null，于是退回举镐。实测一场 58 秒的高级守卫仗里
**手上那件东西翻了 56 次（约每秒一次），65% 的时间举着镐在打怪**，还有 0.7 秒是
箭在半空、手上已经换成镐。改成「没有目标时保持原样」后：0 次翻转、全程举弓。

**2. 弓被玩家自己的头挡住，一个像素都看不见。** `visible`、父链、NDC 全部正常
（NDC 就在画框正中），纯粹是兜帽（球心 y=2.25、半径 0.58，比弓高一米）盖住了。
往左推、往前推、抬高都试过，只是把「哪些朝向会被挡」换一批——手持物跟着玩家转，
**总存在一个朝向让固定偏移正好指向视线深度方向**，固定偏移解决不了。最后走这个工程
既有的那套办法（守卫剪影、眼睛、血条、封印巨龙都是这么处理的）：关掉深度测试、
`renderOrder` 抬到 6。顺带把弓缩小到 `BOW_RADIUS` 0.56 并压到胸口高度 1.15——
等真人比例的 1.4 米弓在八十来像素高的角色上横跨整个身子，读成头盔装饰而不是手里的弓。

`BOW_REST` 还修了一处静默失效：构造里写 `z=0.3`、`updateBowPose` 每帧又写回 0.24，
构造那个数从第一帧起就没生效过。现在后坐绕 `BOW_REST.z` 抖，两处读同一份。
