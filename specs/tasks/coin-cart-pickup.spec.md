# Task: 金币自动拾取与跟随矿车

## 背景与动机

当前地面金币虽然会在一定距离内吸向英雄，但最终拾取判定较小，玩家经常需要贴近或折返。已有背部金币组只能瞬时显示三列金币，拾取和建造支付之间缺少连续、直观的视觉反馈。

本任务以跟随英雄的小矿车替代背部金币：拾取金币时金币飞入矿车，支付时再从矿车飞入建筑格。

## 目标

玩家接近金币即可稳定自动拾取，并能通过英雄身后矿车中的金币堆直观看到持有量。金币从地面飞入矿车、从矿车飞入建筑格，形成完整可读的资源流转。

## 2026-08-28 修订：小型自主矿车与单柱金币

本节覆盖下方原有矿车造型和多列金币布局：

- 矿车整体尺寸缩小，保持容易识别但不抢占英雄和战斗画面的视觉中心。
- 删除连接英雄方向的两根拉杆；矿车表现为自主跟随，不暗示由英雄拖拽。
- 矿车内不再使用多列金币，改为车斗中央一根垂直金币柱。
- 金币柱逐枚向上增长，优先保证拾取飞入、库存增减和支付飞出的动画清晰可见。
- 可见金币达到上限后保持最高柱，HUD 继续显示真实数量。

## 行为与视觉规格

### 拾取

- 地面金币落稳后，在 `7.5` 世界单位内开始吸向英雄后方的矿车。
- 金币进入约 `1.4–1.7` 世界单位收取范围后，沿抬高的弧线飞入矿车。
- 金币到达矿车后才增加真实金币数、更新 HUD 并播放拾取音效。
- 连续拾取多枚金币时允许同时飞行，但使用轻微时间或高度差避免完全重叠。

### 跟随矿车

- 矿车独立存在于场景中，追踪英雄身后约 `1.3–1.6` 世界单位的位置。
- 使用帧率无关的平滑追踪及旋转，不瞬间刚性切换位置；英雄转弯时有轻微拖尾。
- 矿车为纯视觉对象，不加入玩法碰撞，也不阻挡英雄或敌人。
- 矿车不带连接英雄的拉杆或牵引结构，视觉上明确为自主跟随。
- 矿车车斗、侧板和车轮整体缩小约 `20%–25%`。
- 矿车位置受当前通道安全宽度约束，减少狭窄矿道中的穿墙。
- 车轮按矿车移动距离转动；停止后不继续空转。

### 金币堆

- `0` 枚时显示空车。
- `1–12` 枚逐枚增加可见金币，全部在车斗中央垂直堆成一柱。
- 超过可见上限时保持满载外观，HUD 数字继续显示真实数量。
- 每次金币落入时，新增金币有短促缩放/弹跳反馈。

### 支付

- 每扣除一枚金币，优先从矿车可见金币堆顶部取出一枚并飞向建筑格。
- 飞行起点必须使用金币在场景中的真实世界坐标，避免对象换父节点时跳变。
- 实际金币数超过可见上限时，支付后矿车仍可保持满载，直到数量降到可见上限以下。
- 矿车尚未创建或没有可取 Mesh 时，从矿车位置生成临时金币作为安全回退。

## 风险与注意事项

- 当前项目是大型单文件，新增逻辑应复用现有 `shared.coin`、`shared.coinMat` 和 `effects`，避免每次拾取创建 Geometry 或 Material。
- 矿车不参与真实碰撞；通道约束只修正视觉位置，不能反向推动英雄。
- 支付时真实库存可能高于可见金币数，必须区分逻辑数量与表现数量，不能以 Mesh 数量作为扣款依据。
- 连续飞入金币尚未入账时要保留独立状态，避免被 `coinDrops` 的普通吸附逻辑重复处理。

## 备注

- 矿车采用现有基础几何体制作原型，优先验证轮廓、跟随手感与资源流向；后续可无缝替换正式 GLB 模型。
- 参考图中的竖向金币视觉改为矿车内分层堆叠，以避免遮挡英雄上半身和武器动作。
